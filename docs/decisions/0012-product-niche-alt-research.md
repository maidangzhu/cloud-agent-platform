# ADR-0012：产品壳收窄为"开源平替技术方案调研 Agent"

**状态：** 已接受（2026-07-03）

## 决策

产品壳（对外定位）收窄为：**开源平替技术方案调研 agent**。

> 给定一个热门的闭源 AI 产品（如 Manus、Cluely、Cursor、Perplexity），agent 全网 + GitHub 搜索它的开源替代方案（如 OpenManus、Pluely），读取其 repo/README/架构/活跃度，产出一份**可审计的技术方案对比报告**：各开源平替怎么实现的、技术栈是什么、成熟度/与原产品的差距在哪、值不值得自建。

底子仍是 [ADR-0002](./0002-product-spine.md) 定义的通用研究 agent 脊柱（workspace/run/artifact/deep research/sandbox）；本 ADR 只收窄**默认场景、工具倾向、demo 叙事**，不改动架构。

## 背景

探索"通用研究 agent"产品壳时，被"你这个用 Manus 能不能解决"直接击穿——通用叙事过宽，答不出"为什么不用现成产品"。收窄到"平替调研"后，这个问题结构性消失：**Manus 自己不会告诉你它的开源替代品有哪些、实现得怎样**——这是闭源产品结构上无法提供的信息，不存在与之竞争的问题。

## 为什么这个 niche 成立

1. **作者是重度用户（dogfooding）。** 打磨本项目的过程本身就是"调研 agent 产品技术方案"，用户即作者，需求真实不是编出来的。
2. **吃满脊柱能力，不浪费任何硬核设计。** 全网搜（deep research）+ 读文档/源码（fetch_url/read_file）+ 视需要 clone 查活跃度甚至跑一下（sandbox/run_command）+ 带引用的对比报告（artifact + source trail）。
3. **受众真实存在。** "X 有没有开源替代"是 HN / Reddit / V2EX 高频问题。
4. **面试弹药自产自销。** 调研出的技术选型对比本身就是面试谈资。

## 与"搜索 + LLM 总结"的三刀差异（面试话术）

面试官必问："GitHub 搜索 + 把 README 喂给 GPT，五分钟也能做到，你凭什么更好？"

**一句话答案：一个是搜索，一个是尽调（due diligence）。**

1. **广度：** 搜索工具只搜某一个站（如 GitHub）。本项目全网捞（GitHub + HN + Reddit + 博客 + Product Hunt），交叉验证，捞到"活的判断"（如"这个平替其实是玩具"这类讨论），不只是"名字匹配的仓库列表"。
2. **深度（脊柱的核心价值）：** README 会吹牛——三个月不更新、核心功能是 TODO、跑不起来。LLM 只能总结 README 说了什么，不能验证是不是真的。本项目有沙箱，能 clone 下来看 commit 活跃度、issue 状态，P1 甚至能实际跑一遍。**"我不仅读了它怎么说，还验证了它到底行不行"**——LLM 没有手，做不到。
3. **可信 + 可沉淀：** LLM 总结的话不知道哪句是幻觉，聊天记录一关就没了。本项目每个结论挂 source（可追溯到具体 repo 文件/具体讨论），沉淀在 workspace 里，三个月后新平替出现，追加一个 run 即可更新报告，不是一次性问答。

## P0 范围收窄（吸取"B 档工程量过大"的教训）

验证类能力（deep clone + 实际跑起来对比）**不是 P0 门槛**。P0 只需：

- 全网搜索 + 交叉信息源（广度刀）。
- 读 repo 的 README/文件结构 + **commit 活跃度/star 趋势/issue 状态**（轻量深度刀，不需要真的跑代码）。
- 带 source 的结构化对比报告（可信刀）。

"实际 clone 下来跑一遍验证"作为 P1，需要时再加，避免让 P0 膨胀成通用 agent 工程量。

## 被否方案

- **档位 A（通用技术选型调研，如"Kafka vs RabbitMQ"）：** 更宽但更百搭，不一定用得上沙箱，退化为"读文档总结"，差异点弱。
- **档位 B（带完整验证/实跑的技术方案调研）：** 工程量过大，且验证步骤把"调研"做成了"通用 agent"，偏离聚焦。已收窄为 P1 可选能力而非 P0 门槛。
- **档位 C（聚焦 AI 领域调研）：** 受众更窄，且与"平替调研"相比缺少结构性的"为什么不用 Manus"论证。

## 连锁影响

- PRD 用户故事/示例应更新为"平替调研"场景（如 Story 1 的 OpenClaw 对比案例已天然契合，可直接复用）。
- 术语表新增 **Alternative（平替）** 相关概念。
- demo 数据/fixtures（testing-strategy.md）应准备平替调研场景的样例，而非泛化研究主题。
