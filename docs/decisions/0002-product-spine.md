# ADR-0002：产品脊柱锁定为研究工作区 Agent；主动对外划出范围

**状态：** 已接受（2026-07-02）

## 决策

产品脊柱是**研究工作区 agent**——用户发起、有边界、可审计、可取消。能力分三桶：

- **脊柱（P0）：** workspace/thread/run、agent-in-sandbox、artifact + workspace 文件编辑、deep research（全网搜索）、events+SSE、credits、cancel/timeout。
- **兼容加分（P1）：** memory（跨 workspace 记住关键决策/偏好并可加载）、skills（可按需加载的能力包）。二者不改动脊柱架构，只增强 agent 能力。
- **明确排除：** 无人值守的主动心跳、替用户对外发消息/邮件、接管第三方账号。如需相关能力，仅以"生成草稿等用户确认"的降级形式出现。

## 背景

探索期一度考虑转向 OpenClaw 式个人助理（心跳 + 主动对外）。经分析，该形态与 [ADR-0001](./0001-execution-model.md)（发射后不管、无常驻进程、sandbox 不持长期凭证）存在架构级冲突，且依赖多家 OAuth 的官僚审批，技术成长密度低、个人不可控。研究 agent 反而逼出信任边界、scoped token、状态机、幂等事件、SSE 恢复、credit 账本、sweep 收敛等高价值分布式系统能力。

关键洞察：memory / skills / deep research / 通用工作能力，90% 与研究 agent 兼容，无需转向个人助理。真正分叉架构的只有"无人值守、主动、对外建联"这一条。

## 被否方案

- **转个人助理：** 需推翻 ADR-0001、引入常驻调度器 + 长期第三方凭证，违背安全脊柱且受外部审批制约。
- **memory/skills 进 P0：** 会让 P0 变重、周期拉长；作为 P1 引入，风险更低。

## 连锁影响

- memory/skills 需在数据模型和 agent runtime 协议中预留扩展位，但 P0 不实现。
- 术语表新增 Memory、Skill 两条（标注 P1）。
- 与 PRD §4「和 OpenClaw 的区别」、§7「P0 不做多租户」保持一致。

## 补充：项目定性与产品壳收窄（2026-07-03）

打磨中期出现一次自我怀疑："这个功能用 Manus 能不能解决？我到底在做产品还是作品集？"经澄清，项目**双重定性**：

1. **首要目标：工程作品集**，用于找工作 / 短期技术成长。审判标准是"能否独立设计并落地一套经得起拷打的分布式 agent 系统"，**不是**"能否在产品层面打败 Manus"。脊柱的五个工程问题（信任边界、长任务×无状态基础设施、绝不僵死、事实一致性、优雅降级）才是价值锚点，这些是 Manus 类产品内部必解、但其用户永远看不到的问题。
2. **同时要有真实个人产品**，不是纯玩具。因此产品壳不能停留在"通用研究 agent"（过宽、答不出"为什么不用 Manus"），必须收窄到具体 niche，见 [ADR-0012](./0012-product-niche-alt-research.md)。

**结论：一个合理的产品壳（收窄场景）+ 一个经得起拷打的工程核（本 ADR 及后续 ADR 定义的脊柱）。产品壳收窄不改动脊柱架构。**
