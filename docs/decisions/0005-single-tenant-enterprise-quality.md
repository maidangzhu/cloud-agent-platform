# ADR-0005：定位 = 单租户功能范围 + 分布式系统级工程质量

**状态：** 已接受（2026-07-02）

## 决策

产品定位一句话：**单租户的产品，分布式系统级的工程。**

- **企业级功能（多租户、SSO、RBAC、组织、计费为核心）—— 排除。** 对个人作品无用，拖慢进度。PRD §7「P0 不做多租户」保持不变。
- **企业级质量（50 并发不挂、可审计、可观测、可 eval、幂等、优雅降级、绝不永久卡住）—— 目标。** 这是面试真正值钱的部分。

## 背景

探索期表述在"企业级 agent"与"个人研究工作区"之间摇摆。澄清后确认：想要的是"经得起拷打的工程质量"，不是"企业级功能范围"。二者不矛盾。

可观测性 / eval / 看板：

- **可观测性（Observability）：** 系统健康吗、哪里慢？→ 结构化日志（带 runId/workspaceId）、指标、链路追踪。运维视角。
- **Eval（评估）：** agent 干得好不好？→ 输出质量：报告准不准、有无真实 source、任务完成度。需固定测试集 + 打分（人工 / LLM-as-judge）。质量视角。
- **看板（Dashboard）：** 把上面两类喂给人看的界面。

三者均为 **P1**（依赖先有稳定 run 产数据），但 **P0 需在数据模型预留字段**（事件带时间戳、tool call 记 duration、run 记 error 分类）。append-only 事件模型天生是可观测性金矿。

## 被否方案

- **做多租户/RBAC/组织：** 个人作品无价值，拖慢核心。
- **eval/看板进 P0：** 无稳定数据可评，硬塞拖死核心。

## 连锁影响

- 现有 `openspec/changes/agent-eval-monitoring/` 提案方向正确（离线分析脚本），归入 P1。
- 卡死诊断（[ADR-0007](./0007-stuck-diagnosis-model.md)）是可观测性的 P0 骨架。
